## 1. 技术设计链

不要从“使用某插件/算法”开始。按以下链路写：

**可见问题或体验目标 → 可复现案例 → 分层因果链 → 每层输入/输出/失效条件 → 引擎与资产接口 → 成本 → 回退 → 验收**

先选一个贯穿全案的基准案例，固定角色、输入、地形、时间、单位和预期结果，再增加反例。让文档、原型、调试视图和测试使用同一份数据。

把证据分为：

- **实测/源码/现行官方文档事实**：记录版本与适用范围。
- **教学模型或估算**：用于说明趋势，不能冒充实机结果。
- **设计提案**：需要原型或生产验证。

目标引擎、硬件或 API 可能变化时，先查当前资料；不要默记版本参数并当成事实。

## 2. 数据、时间、空间与状态

### 数据契约

每个接口写清：字段、类型、单位、有效范围、坐标空间、时间戳/帧号、来源、拥有者、消费者、更新频率、生命周期、默认值和失效处理。

区分：

- 配置数据、运行时状态、表现状态和持久化数据。
- 请求目标、实际执行目标和最终求解结果。
- 事件、持续状态、快照和命令。
- 权威值、预测值、插值显示值和调试值。

### 时间

明确游戏时间、真实时间、动画时间、服务器时间和 UI 时间。写清暂停、倍速、低帧率、跨周期、大 DeltaTime、丢帧、回滚和延迟补偿。需要帧率无关的平滑时，用基于时间的半衰期，而不是固定每帧插值系数。

### 空间

统一世界/本地/组件/骨骼/屏幕空间，区分点和向量。写清单位、轴向、变换时刻、旋转缩放、移动平台和附着关系。不要用一个无空间、无时间戳的向量跨系统传递。

### 状态与身份

为事件或交互分配稳定身份，例如角色 ID、交互 ID、步次、任务实例和版本。处理旧事件、重复事件、乱序事件和过期快照。明确同帧优先级、互斥、抢占、取消、恢复和对象池复用后的身份重置。

## 3. 预算、失败与回退

### 预算

按目标平台写帧时间、CPU/GPU、内存、IO、网络、查询次数、实体数和资产容量预算。用毫秒和字节做预算，平均帧率只做汇总；同时看分位数、尖刺和长时间热状态。区分流水线并行耗时与端到端延迟。

### 降级

优先保留设计语义，再降低表现成本。例如降低更新频率时保持事件不漏，降低动画精度时保持接触身份，降低远景细节时保持导航与碰撞一致。写清各档画质、LOD、弱机、断线和资源缺失时的行为。

### 拒绝与回退

不是每个请求都必须执行。定义：无有效目标、空间不可达、预算不足、数据过期、资源未加载、身份冲突、网络超时和存档损坏时的拒绝、排队、重试、回退和玩家反馈。回退不能悄悄复活旧状态或制造无限循环。

### 系统边界

说明某功能不负责什么。例如脚部 IK 不负责让胶囊体穿过台阶；局部动画计划失败时由移动/动作选择系统决定停步、改路或切换动作。不要用最后的平滑、权重或特效掩盖上游约束错误。

## 4. 调试和验收

### 可观测性

为每阶段保留输入、输出、拒绝理由、版本、时间和身份。提供重叠调试绘制、状态日志、帧时间线、重放或快照。日志需限频、分类、可开关，避免调试工具本身改变结果。

### 排错顺序

沿数据链找**最早出错的阶段**，再修对应输入或规则。区分计划错误、查询错误、坐标错误、时序错误、求解错误和表现错误。一次只改变一个主要变量，并用同一组基准与反例复测。

### 工程里程碑

按最小闭环安排：

1. **数据**：基准案例、单位、时钟和身份可重放。
2. **核心规则**：正常案例通过，结果可手算或独立核对。
3. **约束**：无目标、边界和拒绝理由正确。
4. **接入**：资产、引擎、网络和存档接口接通。
5. **表现与降级**：反馈一致，弱机和低帧率不破坏语义。
6. **验收**：基准、反例、压力、长稳和回归记录齐全。

每个里程碑写“做成”和“失败”的可观察标准，不只写“功能完成”。

## 5. 典型系统抽象

### 流送/虚拟化

统一问：需求从哪里来、优先级怎样排、预算满了淘汰谁。区分后台 IO/解压与主线程注册；容量不足和单帧卡顿是不同问题。为进入、退出、回头、传送和高速移动准备回退。

### 动画/物理

区分动画意图、预测计划、世界查询、约束求解和最终姿态。检查固定步、子步、时间缩放、根运动、接触锚点、可达性和网络同步。先做一个完整动作闭环，再扩展地形和组合。

### 性能

先把“卡”分类为稳定低帧率、偶发尖刺、热降频、帧节奏不稳或内存/崩溃。固定设备、温度、构建、路线、缓存与画质，比较时控制变量。先找瓶颈再选工具；测量开销和统计误差必须记录。

### 网络

明确权威端、输入、预测、确认、回滚、插值、补偿和断线恢复。检查重复结算、可破坏物/拾取/任务竞争、客户端作弊和延迟下的反馈。视觉平滑不能篡改权威结果。
