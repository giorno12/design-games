## 1. 美术方向契约

先明确：目标玩家、体验支柱、题材与幻想、叙事身份、玩法信息层级、视角与镜头距离、平台、目标设备、内容规模、制作周期、团队能力和技术边界。

把“高级、二次元、写实、干净、有冲击力”等词改写成可观察规则，例如：轮廓差异、明度组织、色彩脚本、材质粗糙度范围、细节密度、线条、比例、运动方式、特效持续时间和 UI 层级。

建立 2–4 条视觉支柱。每条必须能指导取舍，例如“远景靠剪影识别角色职业，近景才展示材质细节”。参考图用于说明具体维度，不把多张互相冲突的图拼成模糊目标。

涉及外观、地点或物体的研究时，寻找可靠来源图像和元数据；记录作者、出处与许可，区分灵感参考、可直接使用资产和需要原创重设计的部分。不要虚构来源或把风格参考当授权。

## 2. 视觉语言与可读性

### 形状与轮廓

用形状语言区分角色、阵营、功能和危险：圆润、尖锐、稳定、失衡、重复、破损等。轮廓应在实际镜头、背景和动作下可辨，不只在正面原画中成立。

### 明度、色彩与材质

- 先用灰阶检查主体、交互物、危险和背景层级，再检查色彩。
- 色彩脚本同时服务地点、情绪、阵营、状态和玩法编码；不要仅靠红绿差异传达关键状态。
- 材质回答表面是什么、怎样使用、经历了什么。磨损与污渍应有结构、历史或功能依据。
- 细节密度用于引导视线；平均铺满细节会消解主体并增加生产成本。

### 构图与视觉层级

检查第一阅读点、第二阅读点和背景支持。游戏画面需要给角色、目标、危险、路径和 UI 留位置；概念插画的构图不一定适合实际操作镜头。

### 动态语言

角色的待机、起步、攻击、受击和失败应保持同一身体与性格逻辑。动画和特效必须表达预备、发生、结果和恢复，不能只追求峰值华丽。

## 3. 各美术专业

### 概念/原画

概念设计需要解决功能、结构、比例、材质、变化和可制作性。关键资产补多视角、拆解、尺度、局部材质与运动约束；不要只交一张气氛图。

### 角色

检查职业/性格/阵营、轮廓、装备结构、动作空间、换装拆件、面部与表情、第一/第三人称镜头、染色和皮肤扩展。与动画、TA 和系统共同确定骨骼、插槽和材质槽需求。

### 场景与道具

从区域身份、地标、路径、玩法空间和叙事痕迹组织场景。模块化资产需统一网格、 pivot、吸附、尺度和接缝；独特资产应服务识别、导航或关键体验。

### 动画

明确动作目的、重心、节奏、接触、预备与恢复。游戏动画还需写取消窗口、根运动、事件、循环接缝、混合、镜像、IK 和不同速度下的可读性。

### 特效

按信息优先级分配亮度、面积、运动和时长。区分施法、命中、危险范围、持续区域、增益和结果；敌方危险不能被友方装饰特效淹没。为低画质、色觉和镜头敏感提供替代。

### UI/UX

建立字体、字号、间距、图标、按钮、焦点、状态和反馈规范。覆盖键鼠、手柄、触屏、安全区、文本扩展、控制器切换、加载/空/错误状态和可访问性。UI 不仅做界面皮肤，也表达系统信息架构。

## 4. 资产任务书与生产

每份资产任务书至少包含：稳定 ID、用途、体验/叙事目标、使用镜头、参考及具体参考维度、尺度、风格规则、交付格式、源文件、LOD/贴图/骨骼/材质预算、插槽与命名、变体、依赖、截止日期和验收截图/场景。

区分源资产与运行时资产。保存可编辑源文件、导出配置、版本和依赖；禁止只保留无法继续修改的导出物。外包或跨团队协作时增加术语、目录、反馈轮次和授权证明。

先做代表性资产通过“风格与生产样件”，确认质量、成本和工具链，再批量生产。不要一开始批量制作最终资产。

## 5. 美术评审

评审按层级进行：

1. **目标**：是否兑现体验和叙事身份。
2. **功能**：实际镜头下的轮廓、路径、危险、状态和交互是否可读。
3. **统一**：形状、色彩、材质、比例、动作和 UI 是否符合支柱。
4. **制作**：结构、预算、复用、命名和导出是否可生产。
5. **表现**：构图、细节、质感和润色。

反馈写“观察 → 影响 → 对应支柱 → 修改方向 → 验证场景”，避免“感觉不对”“再高级一点”。区分必须修正的可读性/一致性问题和可选个人偏好。最终在目标设备、真实光照、运动、战斗密度和不同辅助设置下验收。
