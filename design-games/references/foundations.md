# 设计基础与经典理论的可操作用法

## 目录

1. 理论镜头

3. 学习、难度与公平
4. 拆解游戏的方法

## 1. 理论镜头

以下是概念转述，不是原文摘录。用它们提出问题，不用它们替代具体项目判断。

| 概念来源 | 可借用的镜头 | 使用边界 |
|---|---|---|
| Hunicke、LeBlanc、Zubek 的 MDA | 机制产生动态，动态形成审美体验；分别检查规则、实际行为和玩家感受 | 不是严格线性生产线；测试可从体验反推机制 |
| LeBlanc 的八类趣味 | 感官、幻想、叙事、挑战、社交、发现、表达、消遣可作为体验词汇 | 不必每款游戏全覆盖；选择主次 |
| Salen 与 Zimmerman《Rules of Play》 | 关注意义性游玩：玩家行为与系统反馈之间是否可理解、有后果 | “有选择”不自动等于“有意义” |
| Raph Koster《A Theory of Fun》 | 把乐趣与识别模式、学习、掌握联系起来；检查新信息、练习与精通曲线 | 学习不是全部乐趣，叙事和社交也可持续有效 |
| Jesse Schell《The Art of Game Design》 | 用不同“透镜”重复审视同一方案，例如目标、障碍、选择、惊喜、社区 | 透镜是提问工具，不是评分清单 |
| Tracy Fullerton《Game Design Workshop》 | 以玩家为中心，快速原型、测试、观察并迭代 | 不要把内部喜好当玩家证据 |
| Jesper Juul《Half-Real》 | 同时检查真实规则与虚构包装；找两者相互强化或冲突之处 | 写实包装不能替不一致的规则开脱 |
| Steven Johnson 式可读因果思想 | 让因果、目标和反馈可被玩家推断，减少无意义试错 | 可读不等于没有深度或惊喜 |

常见扩展镜头：自我决定理论中的自主、胜任、关系；心流中的挑战与能力匹配。把它们当可检验假设，不把所有玩家归入固定类型，也不把 Bartle 等玩家分类当作科学诊断。

## 2. 体验与决策

### 从体验目标落到行为

把抽象词改写为行为证据：

- “紧张”：玩家在信息不完整时管理风险，失败前能辨认升级信号。
- “爽快”：输入响应明确，命中因果清楚，短时连续决策不被无关等待切断。
- “策略”：多个可行方案随局势改变价值，信息支持预判而非猜拳。
- “自由”：玩家能选择目标、路径或表达，并承担系统可理解的后果。
- “沉浸”：规则、空间、角色和反馈维持一致的世界逻辑，干扰被有意控制。

### 判断决策质量

问五个问题：

1. 玩家是否理解可选行动及主要风险？
2. 不同选项是否在不同情境下有真实价值？
3. 选择是否改变后续状态，而非只改变动画或数值颜色？
4. 玩家能否从反馈修正心智模型？
5. 决策频率是否合适，是否被重复劳动淹没？

若存在永久显然最优解，先改变情境、代价、信息或协同关系，不要只把其他选项数值加一点点。

## 3. 学习、难度与公平

### 教学节奏

采用“展示安全样例 → 引导操作 → 明确反馈 → 独立测试 → 组合旧知识 → 变化或反转”。不要用长文本代替可操作的练习。

### 难度来源

区分执行精度、知识、判断、资源管理、协作和随机波动。先确认目标难度来自哪一项，再调整对应变量。单纯增加敌人生命通常只延长执行，不会自动增加深度。

### 公平感

公平要求规则一致、关键风险可感知、失败能归因、恢复成本符合情境。随机结果应让玩家理解机会与风险；必要时用保底、样本修正或信息预告控制极端体验，但必须如实表达实际规则。

### 可访问性

把操作难度与理解难度分开处理。考虑重绑定、按住/切换、字幕、色觉替代编码、字号、镜头强度、时间压力和辅助选项。辅助不必破坏核心决策；先确定真正不可移除的体验约束。

## 4. 拆解游戏的方法

不要只列功能。按以下顺序拆解：

1. **体验支柱**：游戏反复兑现哪两至四种体验。
2. **核心循环**：玩家获得信息、做决策、执行、结算和反馈的过程。
3. **状态与资源**：什么被保存、消耗、恢复、转换和竞争。
4. **动态**：玩家实际会发展出什么策略、 exploit、协商或行为。
5. **内容承载**：敌人、关卡、任务、装备怎样制造机制变化。
6. **长期结构**：成长、解锁、社交与目标如何改变核心循环。
7. **反馈与包装**：玩家如何读懂行动、结果和世界规则。
8. **反证**：在哪些玩家、场景或极端策略下体验会崩坏。

输出拆解时区分“可观察事实”和“你的设计推论”。不要从单一成功产品直接推出普遍因果。
