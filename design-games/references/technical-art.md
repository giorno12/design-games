## 1. TA 工作链

TA 不是只写 Shader，也不只是检查面数。把视觉目标转成可复现系统：

**视觉意图/可见问题 → 基准资产与场景 → 渲染或资产数据链 → 输入/输出/失效条件 → 工具与内容规范 → 性能预算 → 降级 → 目标设备验收**

保留“标准球、标准材质、标准灯光、标准角色、标准场景”等基准，避免每个资产用不同条件比较。记录引擎版本、渲染管线、平台、色彩空间和画质设置；版本相关参数先查当前文档或源码。

区分实测、帧捕获、教学示意和估算。不要只凭编辑器视口、单张截图或高端 PC 判断移动端结果。

## 2. 模型、UV、骨骼与贴图

### 网格

按轮廓、形变、遮挡和投影面积分配几何。检查拓扑、法线、切线、硬边、重叠、背面、 pivot、尺度、包围体、插槽、碰撞和导出轴向。高面数不自动等于高画质，低面数也不能以破坏轮廓和动画为代价。

### UV 与纹素密度

明确 UV0/UV1 等通道用途、镜像、重叠、padding、排布、烘焙和光照贴图需求。用屏幕投影和资产尺度制定纹素密度，不盲目全员 2K。检查近景、接缝、mip、过滤、平铺和第二 UV。

### 骨骼与变形

与动画共同确定骨骼数量、层级、命名、绑定姿势、权重数量、辅助骨、表情、换装和重定向。验证极端姿态、体积塌陷、拉伸、法线、布料/物理碰撞和 LOD 切换。

### 贴图

写清分辨率、通道打包、色彩空间、压缩格式、采样器、mip、流送、图集和平台覆盖。法线、遮罩和数据贴图不能随意按颜色贴图处理。压缩后要在目标设备检查带状、块噪、通道串扰和透明边缘。

## 3. 材质、Shader、光照与特效

### 材质与 PBR

物理材质检查能量守恒、金属度、粗糙度、法线、AO、透明和双面。Base Color 不应烘焙直接光照；金属度通常为导体/非导体分类，特殊混合需有表面依据。风格化项目可有意偏离 PBR，但要保持自身规则一致。

### Shader

先写视觉输入和预期输出，再决定节点或代码。记录参数范围、默认值、纹理、坐标空间、时间、插值、精度、分支、采样次数、渲染 Pass、透明排序、阴影、深度、雾、实例化和兼容性。为不支持特性准备回退材质。

Shader 改动需在移动/旋转、近/远、亮/暗、正/背光、阴影、不同曝光和低画质下检查。防止精度、NaN、负值、除零、未初始化历史和时间累积导致设备差异。

### 光照与后处理

建立曝光、主光、补光、天空、雾、阴影、反射和色调映射基准。不要靠后处理修正所有资产问题。检查角色与场景是否共享一致光照，以及昼夜、天气、室内外交互和过场切换。

### VFX 技术

检查粒子数量、发射率、生命周期、透明叠加、材质指令、灯光、阴影、碰撞、贴图、网格粒子和 decal。透明过绘常比粒子数量本身更关键，但必须以实测为准。为低画质保留危险范围和关键时序。

## 4. 性能与 LOD

先区分 CPU、GPU、内存、IO 或发热瓶颈，再优化对应项。TA 常查：Draw/提交、材质切换、骨骼与蒙皮、顶点、像素、透明过绘、阴影、带宽、纹理与网格内存、流送和编译。任何一个计数都不是跨项目通用瓶颈定律。

LOD 依据屏幕误差、轮廓、材质、动画和玩法可读性制定。检查切换距离、回差、 popping、阴影/碰撞/导航一致性、远景替代和内存常驻。高级虚拟几何、实例化或自动 LOD 的能力与限制随引擎版本变化，不能凭名称推断零成本。

纹理内存粗估：`每级字节数 ≈ 宽 × 高 × 每像素位数 ÷ 8`，完整 mip 链约为基础级别的 `4/3`，但块压缩对齐、最小块、数组、平台格式和引擎驻留会改变实际值。用 `scripts/art_budget.py texture` 做初步比较，最终以目标平台统计为准。

## 5. 资产管线和验收

### 管线

定义 DCC 源文件 → 校验 → 导出 → 导入 → 材质绑定 → 平台转换 → 打包 → 运行时验证。固定命名、目录、尺度、轴向、元数据、预设、依赖和版本。自动校验重复 ID、丢失贴图、错误色彩空间、超预算、无效法线、缺失 LOD 和非法材质参数。

自动化失败时给资产作者可理解的原因、路径和修复建议；不要只报退出码。导出应可重复，避免依赖本机隐藏状态。

### 验收矩阵

- 基准资产与极端资产均通过。
- 目标设备、目标分辨率和真实场景，而非只看孤立展示间。
- 静态/运动、近景/远景、室内/室外、昼夜/天气、战斗峰值。
- 高/低画质、LOD、阴影、反射、曝光、色觉与镜头辅助。
- 首次加载、热缓存、流送、长时间运行和发热。
- 源文件、导出预设、依赖、命名和回退资产完整。

问题报告包含资产 ID、版本、设备、画质、复现、截图/捕获、预期/实际、预算和首个异常阶段。先定位资产、材质、光照、后处理、驱动或性能层，再修改。
