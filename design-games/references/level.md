## 1. 关卡设计契约

先明确：目标玩家、能力集合、预计时长、体验曲线、核心教学/考验、叙事任务、前后关卡状态、入口/出口、必经与可选内容、检查点和技术预算。

把“关卡很好玩”拆成可观察目标：玩家能否读图、选择路线、运用机制、理解失败、发现变化、在目标时长内完成。

## 2. 空间与引导

### 空间语法

统一使用：地标、路径、节点、边界、门户、视线、前景/背景、危险区、安全区、奖励区和不可达空间。让同类空间语言保持一致，例外必须有叙事或玩法理由。

### 路径结构

- 线性：便于控制教学和演出，需避免走廊式无决策。
- 分支与汇合：提供选择并控制汇合后的状态。
- 环路：支持掌握捷径和空间理解，避免无意义绕路。
- 中心辐射：适合目标选择和回到枢纽，需防止重复清场疲劳。
- 网络/开放区域：适合系统交互，必须强化导航、局部目标和边界。

“开放”不自动等于“有选择”。分支需要可辨认的风险、收益、体验或表达差异。

### 非 UI 引导

用地标、视线、构图、光照、颜色、运动、声音、敌人布置、道路形状和奖励引导。UI 导航用于补充，不要用它掩盖空间完全不可读。为反向玩家、迷路和跳过剧情的情况保留恢复线索。

### 尺度与移动

从角色速度、转向、跳跃、冲刺、镜头和战斗距离推导尺度。用“通过时间、可用操作、遭遇距离和视线时长”描述，不盲抄厘米数。门、走廊、台阶、掩体和平台必须同时满足逻辑移动、镜头和动画约束。

## 3. 节奏、战斗和解谜

### 节奏

安排：引入 → 练习 → 组合 → 强度峰值 → 释放 → 变化/奖励。休息不是空白，可承载叙事、资源、探索或计划。控制高强度事件的持续时间、密度和恢复。

### 战斗遭遇

明确：玩家入场信息、战斗目标、敌人职责、空间用途、增援条件、资源供给、退出条件和结束反馈。掩体、高差、窄口和侧翼路线必须改变决策；检查出生点是否造成无预警伤害或 AI 互相失效。

用安全样例教学，再独立测试，最后组合或反转。不要靠一次过场解释后立刻高压惩罚。

### 解谜

分离：发现规则、形成假设、执行解法、验证结果。优质提示应恢复思考方向而非直接泄露答案。检查多解、软锁、道具消耗后不可解、顺序破坏、重置和提示升级。

## 4. 开放世界与任务

开放世界按“区域身份 → 地标网络 → 路径选择 → 局部活动 → 系统交互 → 回流动线”组织。不要让所有兴趣点只换奖励数值。密度应服务移动节奏和发现体验，不是地图越满越好。

任务空间需同时检查：任务状态、角色位置、触发体积、时间/天气、战斗与对话互斥、玩家绕序、目标死亡、离开区域、失败重试和存档恢复。叙事节点不能假定玩家只从唯一方向到达。

## 5. 灰盒和验收

### 最小灰盒

先放角色尺度、关键路径、视线、掩体、高度、触发、目标、资源、敌人和检查点。不要等美术完成才验证移动与读图。

### 验收用例

至少覆盖：

- 新玩家无口头指导能否找到首个目标并完成核心操作。
- 逆向、绕行、跳跃、冲刺、速度构筑是否破坏流程。
- 战斗、剧情和任务同时触发时的优先级。
- 死亡、退出、读档、传送和断线后的状态恢复。
- 最短路径、全收集路径和迷路路径的时长与体验。
- 镜头穿模、遮挡、导航、AI 寻路、性能峰值和流送边界。
- 色觉、字幕、镜头敏感和不同输入设备下的可读性。

### 观察记录

记录玩家在哪里停顿、误读、回头、重复尝试、选择意外路线及说出的心智模型。区分“设计希望玩家做的”和“玩家实际做的”。先修阻断理解和核心决策的问题，再修个人审美意见。
